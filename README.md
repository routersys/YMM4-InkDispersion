# 墨拡散 for YMM4

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](#)
[![.NET](https://img.shields.io/badge/.NET-10.0-purple.svg)](#)
[![Release](https://img.shields.io/github/v/release/routersys/YMM4-InkDispersion.svg)](https://github.com/routersys/YMM4-InkDispersion/releases)

---

YukkuriMovieMaker4（YMM4）上で動作する、素材を墨の付置とみなし、格子ボルツマン方程式による吸水紙中の浸透流で墨を外へにじませて描画する映像エフェクトプラグインです。
浸透流のモデルはChu and Taiの論文「MoXi: Real-Time Ink Dispersion in Absorbent Paper」（SIGGRAPH 2005）に基づきます。
履歴フレーム、参照画像、学習済みモデルを使わず、入力された一枚の映像だけを処理します。
にじみの形は紙の繊維とシードから決定論的に決まり、同じ設定では常に同じ形になります。
強さ、拡散度、水量、到達距離、繊維、にじみ止め、粘度、乾燥、濃度、かすれの10項目はアニメーションに対応しています。

## 概要

本プラグインはYMM4の映像エフェクトとして動作し、エフェクトの種類一覧では「墨拡散」として表示されます。カテゴリは装飾とアニメーションです。

入力された現在のフレームのアルファ値から素材の形を求め、素材のセルを表面層の墨だまりとして正方格子の上に置きます。浸透の計算はChu and Taiの論文「MoXi: Real-Time Ink Dispersion in Absorbent Paper」（SIGGRAPH 2005）の格子ボルツマン方程式に基づきます。各セルはD2Q9格子の9方向の分布関数、表面層の水、流動層の顔料、定着層の顔料の状態を持ち、表面からの供給、透過率つきの流走、衝突、顔料の移流と定着のステップを繰り返して墨をにじませます。透過率は紙の繊維むらと礬水と膠と定着した顔料から決まり、乾いた前線のピン止めと蒸発が縁の荒れと縁の濃さを作ります。浸透は決定論的で、同じシードと同じパラメータでは常に同じ形になります。

拡散度のパラメータは、にじみの記録をどこまで表示するかを決めます。各セルには顔料が届いたステップが記録されるため、拡散度を時間で変えると、素材から墨がにじみ広がっていく遷移になります。求めた墨は、定着した顔料の濃さと紙目のかすれを持つ墨として描画し、元映像の上へ合成します。

計算はComputeWeaveの計算シェーダーがDirect3D 12で実行します。YMM4のDirect3D 11側とComputeWeaveのDirect3D 12側は、共有テクスチャと共有フェンスで接続します。通常のフレーム処理では、CPUへの画素の読み戻しを行わず、顔料到達ステップの記録だけを読み戻します。墨が存在する最小の矩形の範囲だけを描画し、素材の形状とパラメータが変わらないフレームでは浸透の計算を再利用します。

このエフェクトはAviUtl向けのEXO出力には対応していません。

## インストール方法

1. [Releases](https://github.com/routersys/YMM4-InkDispersion/releases/latest)ページから最新のプラグインファイル（`.ymme`）をダウンロードしてください。
2. YMM4が起動していないことを確認し、ダウンロードしたファイルを実行してインストールします。
3. YMM4を起動し、タイムライン上のアイテムに映像エフェクトを追加します。
4. 映像エフェクトの種類として「墨拡散」を選択してください。

## 主な機能

### 1. 格子ボルツマン法による浸透流

現在のフレームのアルファ値から素材の形を求め、素材のセルへ水と墨を置きます。水の流れはD2Q9格子の格子ボルツマン方程式で解きます。分布関数の平衡分布はHe and Luoの非圧縮変種を使い、水の少ない場所では移流の項を弱めて負の密度を防ぎます。

流走のステップでは、隣接セルとの間の透過率に応じて分布関数の一部を跳ね返します。透過率は繋がった2つのセルの阻害係数の平均で決まるため、運動量と水の量が保存されます。乾いた前線のセルは、周囲の水の密度がしきい値を下回る間はピン止めされ、水が溜まると解放されます。この繰り返しが、にじみの前線の不規則な進みと縁の荒れを作ります。

顔料は水の流れに運ばれます。新しく濡れたセルへは上流からの分布関数の重みで運び、すでに濡れたセルでは速度を遡る特性曲線法で運びます。紙の繊維に妨げられた顔料は流れから遅れ、乾くにつれて定着層へ移ります。

### 2. 拡散度によるにじみの遷移

拡散度は、にじみの記録をどこまで表示するかを決めます。0%では何も描画せず、値を上げると墨が素材から外へにじみ広がっていきます。各セルには定着した顔料が届いたステップが記録されるため、表示はにじみの順序どおりに進みます。

拡散度を時間で変えると、文字や模様が紙へにじんでいく演出になります。

### 3. 紙の繊維と枝分かれ

繊維は、紙の繊維むらの強さを決めます。繊維むらはシードから決定論的にハッシュ生成した繊維場で、値の高い場所ほど水が通りにくくなります。高いほど流れが妨げられて枝分かれし、低いほど滑らかににじみます。

シードは、繊維場とにじみの形を決める固定値です。シードとセル位置から決定論的に生成するため、同じシードと同じパラメータでは常に同じ形になります。

### 4. にじみ止めと縁の荒れ

にじみ止めは、礬水による浸透の妨げを決めます。高いほどピン止めのしきい値が上がり、前線が止まりやすくなって縁が荒れ、広がりが抑えられます。

かすれは、紙目によるかすれと縁の荒れの強さを決めます。描画の際に、墨の薄い場所を画素単位の紙目で削り、境界を紙目で荒らします。

### 5. 水量・粘度・乾燥

水量は、素材に置く水の量を決めます。表面層の水は紙の繊維の容量に合わせて少しずつ流動層へ吸い込まれるため、多いほど長くにじみ続けて遠くまで届きます。

粘度は、膠による墨の粘りを決めます。高いほど緩和係数が下がって流れが遅くなり、透過率の阻害と定着も強まって墨がその場に留まります。

乾燥は、水の蒸発の速さを決めます。乾きの速いほどにじみは早く止まり、水を失う場所で顔料が定着するため縁が濃くなります。

到達距離は、墨が届く距離の上限を素材の長辺に対する割合で決めます。距離はジャンプフラッドで求めた素材からの距離で判定します。到達距離を大きくするほど計算領域が広がり、処理量が増えます。

### 6. 品質の選択

品質は、浸透格子の解像度と浸透ステップ数の上限をまとめて切り替えます。

| 品質 | 格子解像度 | 浸透ステップ上限 |
|---|---:|---:|
| 標準 | 160 | 720回 |
| 高品質 | 224 | 1080回 |
| 最高品質 | 288 | 1440回 |

格子解像度は計算領域の長辺のセル数です。短辺のセル数は計算領域の縦横比に合わせて決めます。実際のステップ数は到達距離に応じて決まり、上限で打ち切ります。

## 制限事項

- AviUtl向けのEXO出力には対応していません。
- Direct3D 12デバイスを取得できない場合や、YMM4が使うDirect3D 11デバイスとの共有テクスチャおよび共有フェンスを作成できない場合は、エフェクトを適用せず入力映像を表示します。
- 墨の付置の判定には現在のフレームのアルファ値だけを使用します。輝度と色は判定に影響しません。履歴フレーム、外部画像、学習済みモデルは使用しません。
- 計算領域は素材の範囲に到達距離と描画の余白を加えた大きさで、長辺は8192画素が上限です。素材が大きく余白を確保できない場合は、エフェクトを適用せず入力映像を表示します。
- 処理量とGPUメモリ使用量は、計算領域の大きさと品質に応じて増えます。

## 注意事項

- 処理負荷: 最高品質は格子解像度と浸透ステップ数が最も多いため、高品質と標準より処理負荷が高くなります。到達距離を大きくするほど計算領域が広がります。描画は墨が存在する最小の矩形の範囲だけを計算します。
- キャッシュ: 素材の形とにじみを決めるパラメータが変わらないフレームでは、浸透の計算を再利用します。拡散度、濃度、かすれ、墨色だけを変えたフレームでは、にじみを再計算しません。
- 拡散度0%と強さ0%: 拡散度が0%のときは何も描画しません。強さが0%のときは入力を変更しません。
- シードと再現性: にじみの形は、シード、セル位置、浸透ステップから決定論的に算出します。時間値はにじみの生成に使用しません。
- 透明部分: 墨は素材の外側にも描画されるため、出力範囲は素材より広がります。墨は元映像の上へアルファ合成します。
- 更新通知: エフェクトを最初に生成したときに、YMM4の実行中に一度だけ新しい正式版を確認します。更新情報を取得できない場合は通知せず、そのまま動作します。プレリリースは通知の対象に含めません。
- 不具合の自動送信: 想定していない例外が起きたときは、その内容を開発者へ自動で送信します。内容は「不具合の報告」に書いています。
- 本プラグインを使用する前に、YMM4のプロジェクトファイルのバックアップを作成することを推奨します。

## 不具合の報告

本プラグインは、想定していない例外が起きたときに、その内容を開発者へ自動で送信します。同意は求めず、常に送信します。

送信する情報は次のとおりです。

| 種類 | 内容 |
|---|---|
| 例外 | 型の完全名、メッセージ、スタックトレース |
| 発生位置 | モジュール名、関数名、ファイル名、行番号 |
| プラグイン | アセンブリ名、バージョン |
| 実行環境 | OSの名前とバージョン、.NETのバージョン、CPUのアーキテクチャ、論理プロセッサ数 |
| 識別子 | YMM4の起動ごとに決まるセッション識別子、報告ごとの識別子 |

メッセージとファイル名は、送信の前に置き換えを通します。置き換えるのは、Windowsのユーザー名、ユーザーフォルダー、AppDataのパス、マシン名、ドメイン名、メールアドレス、IPv4アドレスです。送信元のIPアドレスは受信側へ渡す手前で取り除いています。

映像の中身とプロジェクトの内容は送信しません。継続して個人を追跡する識別子も持ちません。セッション識別子はYMM4を起動し直すと別の値になります。

送信するのは想定していない例外だけです。本プラグインがエフェクトのプロセッサを作るとき、Direct3D 12の計算資源を確保するとき、フレームごとに更新するとき、エフェクトの入力をつなぎ直すときと、Direct2Dがシェーダーの定数を書き込むときに起きた例外を報告し、その後はYMM4へそのまま渡します。画面の操作やバックグラウンドの処理で未処理になった例外も報告しますが、本プラグインのコードが関わる例外に限ります。本プラグインの外で起きた例外は送信しません。

次の失敗は送信しません。

| 種類 | 例 |
|---|---|
| 効果をかけないだけで済ませるもの | Direct3D 12デバイスを取得できない、YMM4のDirect3D 11デバイスとの共有テクスチャや共有フェンスを作成できない、計算領域が上限を超えるときに、エフェクトを適用せず入力映像を表示したとき |
| 更新の確認の通信の失敗 | GitHubへ接続できない |

送信できなかった報告はYMM4のユーザーフォルダーへ退避し、次回の起動時に送り直します。送信も再送も非同期に行うため、起動と描画が遅くなることはありません。

実装は [YMM4-Telemetry](https://github.com/routersys/YMM4-Telemetry) をサブモジュールとして取り込んでいます。
